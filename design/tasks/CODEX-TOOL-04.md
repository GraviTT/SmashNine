## What the page does
One page where the user picks every candidate once. Title `SmashNine 후보 비교`. All visible text in Korean.

**Rows** (one selection unit each):
1. Every row the current motion viewer shows a pickable candidate for, built from this branch: fighter base and move rows (also candidate-only "new rows" such as victory), monster rows, monster projectiles, dialogue portraits (happy/angry/hurt/shadow). Rows without any non-adopted candidate are left out (the old viewer still shows them).
2. The guardian shockwave `monsters/yggdrasil_root_guardian-shockwave-v1.png` (`new_row`; the motion viewer does not collect this name): its own row in the projectile section, "수호자 전용 지면 충격파 · 새 줄", with the shared `slam_shockwave-v1` shown next to it as a reference tile ("비교용: 공용 v1", not an option in this row). Note under it: 고르면 게임 코드 연결이 필요함.
3. **옛 몬스터 시트 수리본** section: per monster in `legacy` (15), the game sheet `smash-nine-prototype/assets/art/monsters/<id>_sheet.png` and the repaired `art/bakeoff/monsters/legacy/<id>_sheet-fix1.png` side by side, every row of the game's monster table (`RealmMonster.ART_ROWS`, the game's frames and fps) playing in both. Show the QA ids and the `change` line, and the note "새 6줄 후보를 고르면 이 수리본은 필요 없음".

**Tiles in a row:** `지금 게임` (when the game has the row) + every candidate version sorted v1, v2, v3…. Label each candidate `vN · 옛` (in the checkpoint) or `vN · 새 · <card>` (a key of `changes.json` `new`). Under the tiles, one line per new version: `vN (<card>): <change>`. Rows in `no_new_version` get a visible badge `새 버전 없음` and their text. Rows whose new version has `game_repair` get a badge `지금 게임 시트 수리본` (the comparison is the 지금 게임 tile vs the repair). Rows with a new version get a badge `새 버전 N`. New rows (no game row) get `새 줄 — 게임에 아직 없음`.

**Playback:**
- One clock (`requestAnimationFrame`). Every tile in a row plays at **the same fps**: the game's playback fps for that row (the manifest's `fps`, which already includes adopted speeds) when the game has the row, otherwise the newest version's json `fps`. Each tile steps through its own frame count. A row that does not loop holds its last frame about 0.6 s, then restarts. Row header shows `fps N · 프레임 a / b / c`.
- Page controls: 재생/멈춤, 속도 ×0.25–×1.5 (default ×1), 배경 체크/어둡게/밝게, 크기 작게/보통/크게. `prefers-reduced-motion` starts paused.
- Same screen scale inside a row with the feet lines level: draw every tile of a row on a canvas of the row's largest cell, each picture placed so its feet line sits on the same y (fighter rows mix 128 and 192 cells). Projectiles: their json cell, centred. Portraits: fixed box, `object-fit: contain`. `image-rendering: pixelated`.
- Only rows on or near the screen animate, and images load when a row comes near the viewport (`IntersectionObserver`), so a phone does not load ~350 images at once.

**Picking (one choice per row):**
- Radio group per row: one option per candidate version (`v1 · 옛`, `v3 · 새`) + `둘 다 아님` (label `둘 다 아님 · 지금 게임 그대로` when the game has the row, `둘 다 아님 · 게임에 넣지 않음` for new rows). Legacy rows: `수리본 쓰기` / `지금 그대로`.
- A click writes one document at once; an optional memo (≤ 300 chars) saved with `메모 저장`; `고르기 지움` writes `picked: false`. Status per row: `저장 중…`, `저장됨`, or a Korean error that says to click again. Never write on load or while typing.
- Database: `const db = await window.claude?.use?.("db")`; `null` means no database (local file, preview): keep everything else working, disable the pick controls and show `저장은 게시된 페이지에서만 됩니다`. Collection `candidate_picks`; document id `<kind>~<id>~<row>` with kind `fighter` | `monster` | `projectile` | `face` | `legacy_sheet` (id = sheet stem such as `nova_female`, monster id, projectile id, portrait stem; row = row name, `projectile`, `shockwave`, expression, or `sheet`). Fields: `kind`, `id`, `row`, `choice` (`"v3"`, `"fix1"` or `"none"`), `file` (repo path `art/bakeoff/...` of the chosen picture, or `null`), `options` (the versions offered), `picked` (boolean), `note`, `picked_at` (ISO UTC), `viewer: "compare"`, `commit` (the build commit). Subscribe once to the whole collection with `onSnapshot` and show saved choices; only well-formed documents count. Same call style as the motion viewer (`db.collection(...).doc(id).set(...)`, `onSnapshot`).
- Top panel `고른 것`: `고른 줄 P / 전체 N` and a list (form · row · choice · memo) with links that scroll to the row.

**Navigation and counts:** section chips (each fighter form, 몬스터, 투사체, 대화 초상화, 옛 몬스터 시트 수리본); filter 전부 / 새 버전 있는 줄 / 아직 안 고른 줄. Counts at the top: 전체 N줄 · 옛·새 나란히 M줄 (rows with at least one new version) · 게임 시트 수리본 비교 K (ART-86 rows + legacy sheets) · 새 버전 없음 5줄. The build prints the same counts.

**Look:** the motion viewer's family: its fonts (Silkscreen, IBM Plex Sans KR, IBM Plex Mono from Google Fonts) and its color tokens with the same light and dark blocks. Artifact page rules: no `<!doctype>`, `<html>`, `<head>` or `<body>` tags (the publisher adds them); `<title>` and `<meta name="claude:viewport-fit-sides" content="cover">` at the top; side gutter `padding-left: max(16px, env(safe-area-inset-left, 0px))` and the same on the right, on one outer wrapper with `padding-block`; a sticky bar uses `top: env(safe-area-inset-top, 0px)`; `body` has an explicit token background; every color is a token defined on bare `:root` and redefined in `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {…} }` and `:root[data-theme="dark"]`. At 375 px wide: no horizontal page scroll, tiles wrap (two per line), controls wrap. No external scripts. Visible keyboard focus, stable `id` on every control.
