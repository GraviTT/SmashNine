# CODEX-ART-21 · Frey/Luna 프레임별 검토

## 결과 요약

Frey, Luna, Brave Luna의 사용 프레임 69개를 각각 4배 확대 이미지와 행 연속 이미지로
검토했다. 수치 검사는 원본 시트의 바운드, 불투명 중심, 발 위치, 부분 알파, 내부 구멍,
미사용 셀, 양자화 색상 분포를 기록했고, 포즈·실루엣·표정·장비·루프·동작 의미는 별도의
육안 판단으로 기록했다.

- Frey: 2셀 변경. `attack r4c3`의 지나치게 얇은 방패를 완전한 3/4 타원 방패로 재드로잉,
  `shield r5c0`의 발 기준 121→120 정렬.
- Luna: 22셀 변경. `idle r0c1/r0c2`의 깨진 별 지팡이 머리를 재드로잉, 18셀 발 기준 정렬,
  13셀의 혼합 부분 알파를 하드 알파로 정리했다(항목은 겹침).
- Brave Luna: 20셀 변경. 13셀 발 기준 정렬, 14셀 부분 알파 정리(항목은 겹침).
- 사용하지 않는 셀은 모두 투명이다. 변경되지 않은 사용 셀은 Frey 21, Luna 1,
  Brave Luna 3개이며 픽셀 데이터가 원본과 동일하다.

### 측정과 육안 판단의 분리

**측정값**은 `measurements.csv`, `palette_summary.csv`, `verification.csv`에서 재현할 수 있다.
초기 시트는 Frey가 부분 알파 0, Luna 62,740px, Brave Luna 65,578px이었고 최종 세 시트는
모두 0px이다. 최종 지상 프레임은 모두 발 y=120이며, 미사용 셀의 비투명 픽셀은 0이다.
최종 idle/walk 이웃 프레임의 최대 불투명 중심 이동은 Frey 0.9px, Luna 5.4px, Brave 1.3px,
최대 높이 변화는 모두 2px이며 감사 기준 8px 아래다. 셀 최소 여백은 각각 7/6/7px다.
8단계 RGB 양자화 상위색은 Frey가 암색·남색·금색·백색, Luna 두 형태가 분홍·보라·백색
중심으로 유지된다. 이 수치는 정렬·알파·색상군의 일관성만 말한다.

**육안 판단**은 아래 표의 `육안 판단` 열이다. 얼굴이 같은 인물로 보이는지, 검·방패·별
지팡이·건틀릿의 크기가 자연스러운지, 포즈가 실제 동작으로 읽히는지, 1배 실루엣이 충분한지는
수치만으로 확정하지 않았다.

재드로잉은 built-in ImageGen을 사용했다. 프롬프트의 공통 불변 조건은 “원화의 얼굴·복장·색·
비율, 편집 대상의 몸·무기 자세, 이웃 행의 픽셀 크기를 유지하고 지정 소품만 바꾸며 투명 배경,
하드 픽셀 가장자리, 텍스트·워터마크 없음”이다. Frey는 공격 4번의 방패를 완전한 3/4 타원으로,
Luna는 idle 2·3번의 지팡이 머리를 완전한 청백색 5각 별로 지정했다. 원본 생성 결과와 128px
후처리 후보, 최종 프롬프트 세트는 `generated_sources/`에 보존했다.

## 기술별 추가 행 제안 (아트는 만들지 않음)

현재 `PlayerBase._start_attack()`은 모든 공격에 `attack`을 재생하고, Frey와 Luna의 직접 시작
루틴도 같은 행을 부른다. 아래는 기본 측면 공격에 현재 행을 남기는 전제의 최소안이다.

### Frey

현재 공유: J 3연격, 위/아래 J, 공중 위/아래/옆 J, K 대시 스트라이크, L 라이징 클리브,
L 재입력 스파이크, I 지상 강림과 공중 급강하.

| 추가 행 | 프레임 | 최소 포즈 |
|---|---:|---|
| `attack_up` | 4 | 낮은 준비 → 아래에서 위로 검 이동 → 머리 위 활성 → 착지/회수 |
| `attack_down` | 4 | 어깨 준비 → 몸 낮춤 → 전방 아래 활성 → 검끝 회수 |
| `attack_air_side` | 4 | 공중 몸통 비틀기 → 검 뻗기 → 수평 활성 → 다리 재정렬 |
| `dash_strike` | 4 | 압축 자세 → 방패 뒤 돌진 → 검 선두 활성 → 제동 |
| `rising_cleave` | 5 | 깊은 준비 → 상승 시작 → 수직 검호 활성 → 최고점 → 공중 회수 |
| `spike_followup` | 4 | 공중 재장전 → 전방 크게 쓸기 → 하향 활성 → 행동 잠금 자세 |
| `descent` | 6 | 지상/공중 충전 → 검·방패 모음 → 수직 낙하 → 착지 압축 → 양쪽 충격파 → 회수 |

### Luna 일반형

현재 공유: 별빛 J의 옆/위/아래와 공중 3방향, K Star Comet, L Moon Ring, I 변신 시작.

| 추가 행 | 프레임 | 최소 포즈 |
|---|---:|---|
| `star_up` | 4 | 지팡이 낮춤 → 머리 위로 그리기 → 상단 별꽃 → 회수 |
| `star_down` | 4 | 앞발 내딛기 → 지팡이 하강 → 지면 별꽃 → 세워 복귀 |
| `star_comet` | 4 | 방향 조준 → 별 압축 → 혜성 방출 → 반동 |
| `moon_ring` | 5 | 몸 중심에 지팡이 모음 → 우측 반원 → 좌측 반원 → 완전한 고리 → 해제 |
| `transform` | 6 | 가슴 앞 집중 → 리본·머리 상승 → 빛에 감싸임 → 폭발 → 건틀릿 생성 → Brave 자세 |

### Brave Luna

현재 공유: 잽/보디 킥/회전 킥, 위 어퍼컷, 아래 다리 후리기, 공중 옆/위/아래 J,
K Comet Drive, L 지상/공중 Luna Breaker, I 재입력 Heart Laser. 현재 4프레임 공격행은 먼저
6프레임 콤보(가드 → 잽 접촉 → 킥 준비 → 보디 킥 → 회전 킥 → 회수)로 확장하는 것이 좋다.

| 추가 행 | 프레임 | 최소 포즈 |
|---|---:|---|
| `brave_upper` | 4 | 웅크림 → 별빛 어퍼 활성 → 상승 신전 → 공중 회수 |
| `brave_low` | 4 | 축발 고정 → 다리 낮춤 → 지면 쓸기 활성 → 일어서기 |
| `brave_air_side` | 4 | 무릎 접기 → 비행 발차기 → 전진 신전 → 공중 제동 |
| `brave_dive` | 4 | 공중 방향 전환 → 발 아래 정렬 → 급강하 활성 → 착지 잠금 |
| `comet_drive` | 4 | 주먹 압축 → 방향별 몸 정렬 → 건틀릿 선두 돌진 → 제동 |
| `luna_breaker` | 6 | 지상 회전 준비/강킥/회수 3장 + 공중 각도 전환/하향 강킥/회수 3장 |
| `heart_laser` | 6 | 두 손 모음 → 하트 핵 충전 → 전방 고정 → 지속 발사 → 소진 → 변신 해제 |

## 검증

- 짧은 실제 런타임 캡처를 Frey와 Luna 각각 실행해 공격 1~4프레임이 게임 안에서 순서대로 표시되는 것을 확인했다.
  캡처는 `runtime_frey/attack_frame_1.png`~`attack_frame_4.png`,
  `runtime_luna/attack_frame_1.png`~`attack_frame_4.png`에 있다.
- `tests/test_sprite_frames.gd`: 통과, 8시트 184프레임.
- `tests/analysis/lead/frame_audit.gd`: 새 플래그 0. 기존 허용 소스 가장자리 7개만 표시.
- `verify_sheets.gd`: 통과. changed Frey/Luna/Brave = 2/22/20, 부분 알파 0,
  모든 지상 프레임 feet=120, 미사용 셀 투명.
- 짧은 캡처 스크립트의 최초 작성 때 지역 변수 타입 추론 Parse Error가 1회 있었고 타입을 명시해 수정했다.
  수정 후 최종 Godot 검증·런타임 캡처 로그에는 알려진 샌드박스 노이즈
  `Failed to read the root certificate store` 외 오류가 없다.

## 사람이 판단할 부분과 남은 작업

- 생성 프레임 3개의 미세한 얼굴·머리카락 차이가 실제 7fps idle/14fps attack에서 자연스러운지.
- 하드 알파로 정리한 Luna 계열 마법광이 실제 배경 위 1배에서 너무 딱딱하지 않은지.
- Brave attack 3번의 낮은 횡타가 보디 킥으로 충분히 읽히는지. 본 보고서는 추가 행을 권장한다.
- 기술별 추가 행은 제안만 했으며 그리지 않았고, 제품 코드·기존 테스트도 수정하지 않았다.
- CPU가 무거운 동시 봇 분석을 방해하지 않기 위해 전체 경기 소크는 실행하지 않았다.
- Brave Luna의 별도 짧은 런타임 캡처는 동시 실행 중인 Godot와 `user://logs` 파일명이
  충돌해 엔진 시작 단계에서 완료하지 못했다. Brave 시트는 4배 육안 검토, 공용 프레임
  테스트, 정적 감사와 시트 검증으로 확인했다.
