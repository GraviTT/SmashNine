# CODEX-ART-17 결과 보고

## 완료

게임 내 아트 QA에서 지적된 지진 경고/충격, 덩굴 다리, 아스가르드 광선, 무스펠하임 불기둥, 몬스터 배경 위장, 유키 봉인 부적을 교체·보강했습니다. 신규 원화는 built-in ImageGen으로 생성했고, 최종 게임 파일은 Godot 4.7 `Image` API 빌드 스크립트로 크기·팔레트·알파·프레임·타일 경계를 결정적으로 정리했습니다.

## 수치 검증

`verification.txt`에서 다음을 Godot 이미지 픽셀 단위로 확인했습니다.

- 카드에 지정된 12개 PNG 크기 전부 일치.
- 몬스터 시트 576×384, 96×96 셀 6×4 유지.
- `light_beam_mid` / `fire_pillar_mid`: 각 6프레임 위·아래 4행 불일치 픽셀 **0**.
- `quake_warning` 4프레임 / `vine_bridge`: 좌우 경계 불일치 픽셀 **0**.
- 결과 PNG를 2배/4배 최근접 확대해 직접 확인했습니다.
- 빌드 스크립트를 연속 2회 실행한 뒤 12개 최종 PNG의 SHA-256을 비교했고 불일치 파일은 **0개**였습니다.

빌드 실행 결과는 `ART17_BUILD_OK`였습니다. Godot의 `Image.load_from_file` export 경고는 에디터 런타임용이 아닌 제작 스크립트에서 직접 PNG를 읽기 때문에 발생합니다. 마지막 certificate-store ERROR는 카드에 기재된 샌드박스 노이즈입니다. 그 외 parse/runtime 오류가 없는 최종 빌드를 사용했습니다.

## 리드 통합 메모

1. `quake_warning`은 플랫폼 길이에 맞춰 현재 프레임의 96×16 셀을 수평 반복하고, `quake_impact`는 각 플랫폼 충돌점에 하단 중앙을 맞춥니다.
2. 광선/불기둥은 base를 바닥에 놓고, 선택한 mid 프레임 하나만 128 px 단위로 반복/마지막 크롭한 뒤, 최상단에 top의 하단 중앙을 연결합니다. 전체 시트를 늘리지 않습니다.
3. import는 filter/mipmap off, repeat는 코드/Region 반복 방식에 맞춥니다. 아트 자체의 경계 픽셀은 일치합니다.
4. 몬스터 런타임 셀 크기와 애니메이션 인덱스는 바꾸지 않아야 합니다.
5. 봉인 부적은 4 fps loop를 권장하며, 5초 대기 중 마지막 프레임 고정 대신 계속 순환하는 편이 맥동이 자연스럽습니다.

## 사람이 최종 판단할 부분

- 실제 카메라 줌/배경 dim이 적용된 경기 화면에서 몬스터 림이 너무 강하지 않은지.
- 1080 px 광선과 690 px 불기둥에서 mid 애니메이션 속도가 지나치게 부산하지 않은지.
- base가 각 렐름 플랫폼 표면과 만나는 높이 및 top이 화면 밖으로 잘릴 때의 처리.
- 유키 옆에 배치했을 때 부적의 64 px 시각 크기와 캐릭터/포털과의 우선순위.
- 지진 경고 8 fps와 실제 경고 시간의 동기감.

제품 코드 통합과 실제 인게임 캡처는 이 카드의 쓰기 금지 범위이므로 수행하지 않았습니다.

### 검증

`round2_fix.gd`를 Godot 4.7 headless로 실행해 `ART17_ROUND2_OK`를 확인했습니다. 실행 로그는 [`round2-godot.log`](round2-godot.log)에 보존했습니다. 로그의 인증서 저장소 오류 한 줄은 카드에 명시된 샌드박스 잡음이며, 그 외 parse/runtime/error 줄은 없습니다.

재실행 스크립트는 원본을 `round2_before_*.png`에 한 번만 보존하고 항상 그 원본에서 결정적으로 다시 빌드하므로, 반복 실행해도 보정이 누적되지 않습니다.
최종 PNG 3개, 검증 PNG 3개, 수치 파일을 연속 두 번 빌드해 SHA-256을 비교했으며 7개 모두 일치했습니다.

### 리드 통합 메모와 사람이 판단할 부분

1. 파일 크기, 프레임 수, 셀 크기, fps, 앵커는 기존 통합 값을 그대로 사용하면 됩니다. 코드 변경은 필요하지 않습니다.
2. 실제 게임에서 1080 px 광선과 690 px 불기둥을 각각 최소 한 주기 재생해, 공통 4행 경계가 배경 dim과 움직임 속도에서 과도한 가로 마디처럼 보이지 않는지 사람이 최종 판단해야 합니다.
3. 지진 충격은 이제 2차 폭발이 아니라 단일 burst-and-settle입니다. 마지막 두 프레임의 넓은 먼지 실루엣이 플랫폼 폭에 적절한지 인게임에서 판단해야 합니다.
4. 이 유닛은 제품 소스 쓰기가 금지되어 있어 리드의 통합 장면을 다시 캡처하지 못했습니다.

### 검증 및 리드 통합 메모

`round3_fix.gd`를 Godot 4.7 headless로 실행해 `ART17_ROUND3_OK`, 종료 코드 0을 확인했습니다. 스크립트는 크기, 128행 채움, 32 px 최소 채움, 가장자리 폭 ±2 px, 중심 ±2 px, 몸통 최대 폭 비초과, 접합 RGBA 차이 0.1 이하를 실패 조건으로 검사합니다. 실행 로그의 certificate-store ERROR 한 줄은 카드에 명시된 샌드박스 잡음이며, `Image.load_from_file` 메시지는 제작 스크립트의 직접 PNG 로드 경고입니다. 그 외 parse/runtime 오류는 없습니다.

리드는 기존 통합 값을 그대로 사용하면 됩니다. 현재 애니메이션 프레임 하나의 96×128 셀을 먼저 선택하고, 그 셀을 기둥 높이만큼 세로 반복한 뒤 base/top을 붙입니다. 서로 다른 프레임을 위아래로 연결하지 않습니다.

사람이 실제 게임에서 최종 판단할 부분은 1080 px 광선과 690 px 불기둥을 각각 한 주기 이상 재생했을 때 접합 위치가 배경 dim과 카메라 줌에서도 눈에 띄지 않는지입니다. 특히 불기둥 1·5·6번의 굵은 밝은 무늬가 자연스럽게 흐르는지 확인이 필요합니다. 제품 코드 쓰기가 금지되어 있어 이 유닛에서 새 인게임 캡처는 만들지 못했습니다.
