# CODEX-VFX-01 — 리오 공중 추가 점프 후보

완료: 내장 image_gen으로 3안 × 2상태, PNG 6장과 JSON 6장을 제작했다. 후보만 만들었으며 게임 파일 수정·통합·커밋은 하지 않았다. **앵커 항목은 카드 문구와 충돌하므로 FAIL/확정 대기**다. 그 외 아래 검사는 통과했다.

- A: 얇은 마력 발판 → 갈라짐 → 아래로 떨어지는 조각.
- B: 작은 보석 파편을 아래로 차내는 모양.
- C: 납작한 타원 파문 → 끊어진 호 → 잔여 조각.
- `-1` 첫 추가 점프, `-2` 마지막 추가 점프. 마지막은 청백색 면을 강조했다.

## 측정

모든 스트립: 320×64, 5프레임, 알파 `{0,255}`, 빈 테두리 PASS. `발 위 픽셀 수`는 프레임 좌표 y<3에 있는 불투명 픽셀 개수이며, 높이와 구분한다.

| 스트립 | F1~F5 발 위 픽셀 수 | F1~F5 발 위 높이(px) | 마지막/첫 밝기 합 |
|---|---|---|---|

| A-2 | 1 / 10 / 0 / 0 / 0 | 1 / 2 / 0 / 0 / 0 | 1.646배 |
| B-1 | 3 / 10 / 0 / 0 / 0 | 1 / 2 / 0 / 0 / 0 | — |
| B-2 | 3 / 14 / 0 / 0 / 0 | 1 / 2 / 0 / 0 / 0 | 1.672배 |
| C-1 | 10 / 56 / 0 / 0 / 0 | 1 / 2 / 0 / 0 / 0 | — |

밝기 합은 모든 프레임의 불투명 RGB에 `0.2126R+0.7152G+0.0722B`를 합한 비교 지표다. 실제 사람의 순간 판독률을 뜻하지 않는다.

## 앵커 충돌 및 통합 주의

카드가 요구한 아래 중앙 `(32,63)`을 그대로 발에 맞추면, PNG 안의 픽셀은 발 위에만 놓인다. 따라서 ‘발 아래로 파편 분산’과 동시에 만족할 수 없다. 이번 후보는 **발밑 배치 우선의 임시 앵커 `(32,3)`**를 사용한다. 질문에 대한 확정 답을 받지 않았으므로 카드 변경이나 승인으로 간주하지 않았다.

현재 `Vfx.gd`는 `sprite.centered=false`, `sprite.offset=-anchor`다. 채택 시 위쪽 앵커를 확정하거나, 아래 중앙 앵커를 유지하면서 추가 그리기 오프셋 `(0,+60)`을 지원해야 같은 위치가 된다. 후자는 현재 런타임에 적용된 기능이 아니라 대안 설명이다. 제품 코드는 수정하지 않았다.

보드는 실제 128px 기본 시트의 4번째 줄 첫 칸을 그대로 쓴다. 코드 기준점 `(64,120)`에 맞췄으며, 점프 자세의 최하단 픽셀은 남 y=108, 여 y=112로 기준점보다 12px/8px 위에 있으므로 보드에서 발과 효과 사이 간격이 보인다. 이를 감추기 위해 캐릭터를 옮기지 않았다. 인접 README의 64px/7줄 설명은 구식이며 실제 시트 768×1024와 `Rio.gd`의 8프레임 걷기 행 기준을 따랐다.

## 제작·검증 및 사람이 판단할 것

원화마다 첨부 1(리오 기준 시트), 첨부 2(K 궤적 금지 형태)를 참조로 전달했다. 알파 128 기준 이진화 → 행·칸 분리 → 불투명 영역 크롭 → 안별 공통 비율로 NEAREST 축소(확대 없음) → 리오 계열 팔레트 정리 → 64px 캔버스 패딩 순서다. 보드 확대만 4배다. `build.py`의 assert 검사와 6개 상태 보드(남녀 각각 5칸)의 육안 검수를 수행했다. 게임 실행 및 실제 속도의 모션 검증은 하지 않았다.

다음 권장 단계는 앵커 해석 확정과 후보 선택이다. 사람은 **0.125초에 마지막 점프가 구별되는지**, 발을 딛는 느낌과 현재 발끝 간격, 리오 아트와의 밀도·밝기 조화, K 순간이동/L 방패와의 구별을 판단해야 한다. A는 발판 의미가 가장 직접적이고, B는 보석 모티프, C는 가장 얇은 실루엣을 제공한다.

재현: `PYTHONDONTWRITEBYTECODE=1`을 설정한 뒤 지정된 Python으로 `reports/codex-vfx-01/build.py` 실행. numpy/Pillow만 사용하며 패키지 설치는 하지 않았다.
