# CODEX-VFX-09 A — 날카로운 순간

**완료:** Luna 발걸음·점프·공중 점프 3종, Brave Luna J 후속 7종·보통/강한 적중 여운 2종, 총 **12종 108프레임**을 후보로 제작했다. 첫 순간의 흰 예각 선과 분홍·금색 별이 빠르게 작아진다. 게임 소스·pixelfx 원본은 변경하지 않았으며 다른 후보의 폴더와 파일은 열지 않았다.

## 측정한 값

모든 시트의 첫 가시 프레임과 밝기 정점은 **F1, 0초**다. 정점은 `sum(max(R,G,B))`가 가장 큰 프레임이며 체감 타격감이 아니다. 크기는 모든 프레임의 알파 픽셀을 합친 외접 상자다. 시간은 게임 속도 100% 기준 `frames/fps`다.

## 시각적 확인과 수정

[전체 검수 보드](board.png)는 12종의 첫 프레임을 실제 게임 그림과 함께 **1배와 최근접 4배**로 보여 준다. [전 프레임](qa/)은 각 프레임의 재생 시각을 표시한 1배 접촉시트와 4배 페이지다. [대표 장면](overview.png), [4종 시간 미리보기](timing.apng)도 있다.

**Godot 경기 캡처가 아닌 게임 아트 벤치 합성**이다. 몸 위치는 고정하고 동작 그림·이펙트 프레임을 해당 시각에 맞춰 진행했다. 러시는 타격 셀 F2/F4/F6, 방향 공격은 F3부터 채택 속도로 진행한다. 기존 `luna_brave_slash` 36fps·두께 0.62배, `luna_star_bloom`의 기술별 길이·크기·뒤쪽 레이어, 적중 불꽃 44fps를 함께 그렸다. 돌진·넉백·점프 물리 이동·히트스톱·조기 러시 적중은 재현하지 않았다.

검수 단계:
1. 초안 굽기에서 급강하 캔버스가 짧아지는 문제를 발견하고 원본 캔버스를 늘렸다.
2. 전 프레임 1배 합성에서 낮은 후리기의 별이 발 밑으로 퍼지는 것을 확인해, 초기 별을 발 위쪽으로 올리고 간격을 줄였다. 적중 여운은 몸·머리카락에서 더 떨어뜨렸다. 공중 점프 검수 화면 아래쪽도 넓혔다.
3. 최종 **108프레임 전부를 실제 스프라이트 위 최근접 4배 이미지로 직접 열어** 별의 모양, 몸과의 간격, 끝 프레임 소멸, 잘림을 확인했다. 보드는 확대 부분에서 몸이 잘리지 않게 전체 그림으로 다시 만들었다.

## 자동 검사 결과

원자료는 [measurements.json](measurements.json), 검사는 [audit.json](audit.json)이다.

- 12/12 통과. 빈 첫 프레임·빈 저장 프레임 **0**. 모든 원샷은 `t=duration`에서 빈 그림이다.
- 알파 0/255 이외 **0픽셀**, 1px 테두리 침범 **0픽셀**, RGB 최댓값 40 미만 잔여 **0픽셀**.
- 48px 확장 캔버스로 굽기 전 검사: 잘리는 유효 픽셀 **0**. 여백을 자른 PNG와 원본의 앵커 기준 RGBA 불일치 **0**. 같은 입력을 다시 그린 해시 일치.
- 지정 머리 영역과 몸 중앙 보호 영역에 새로 그린 픽셀 **0**. Luna는 발 기준 `abs(x)<48, y<−40`, Brave는 몸 중심 기준 머리 `abs(x)<48, −100≤y<−24`, 중앙 `abs(x)<20, −24≤y≤24`를 검사했다. 모든 캐릭터·모든 자세의 실루엣을 검사했다는 뜻은 아니다.
- 중력은 방향 계산 뒤 화면 y에 더하며 바닥 충돌·튀어 오름은 없다. `x/y/flip/angle`을 사용자 정의 옵션으로 쓰지 않는다.
- 공유 PC의 Node 원본 그리기 30회 표본: 중앙값 **0.16~0.71ms**, p95 **0.54~5.30ms**. 항상 2ms 미만이라는 기준은 입증하지 못했다. 이는 구워진 PNG를 재생하는 Godot/웹 성능이 아니다.

## 사람 판단과 남은 작업

**관찰:** 기존 별 폭발과 베기 그림이 매우 밝아 새 별 일부를 덮는다. 새로운 몸 중앙 안개는 없고, 새 그림은 공격 끝과 맞은 몸 양옆에 집중한다. 기존 어퍼컷 베기·적중 불꽃이 몸과 겹치는 모습은 새 후보의 그림이 아니다.

**사람이 판단할 것:** 짧은 첫 순간이 0.85배 경기에서 읽히는지, 기본 그림에 더한 작은 별이 타격감을 높이는지, 3연타 중 과하지 않은지, 보통/강한 적중이 충분히 다르게 느껴지는지. v2와 같은 체감 세기인지는 수치만으로 확정하지 않는다.

**남은 작업:** 리드가 실제 경기의 지금/A/B를 시안 월드컵에서 비교하고 채택한 것만 연결한다. Godot 통합·8인 경기·웹 누적 p95/p99·적중당 1회·F2·은신 검사는 수행하지 않았다. 후보 제작 범위 밖이다.

## 재현과 인계

- Luna: `node art/bakeoff/effects/pixelfx/luna/a/bake-vfx09.mjs` (기존 VFX-08의 `bake.mjs`는 보존).
- Brave: `node art/bakeoff/effects/pixelfx/luna_brave/a/bake.mjs`.
- 검수: `node reports/codex-vfx-09-a/qa.mjs --animation`, 검사: `node reports/codex-vfx-09-a/audit.mjs`.
- 읽기 전용 pixelfx core를 절대 URL로 가져온다. 게임 아트 벤치·APNG 유틸은 기존 **A** 보고서 `reports/codex-vfx-08-a/{bench,apng}.mjs`를 읽는다. 추가 패키지 설치 없음.
- `.git`은 세션 권한상 읽기 전용이므로 커밋하지 않았다. [commit.ps1](commit.ps1)은 [manifest.json](manifest.json)에 적은 이번 파일과 작업 카드만 추가·커밋한다. 강제 추가는 하지 않는다.
