# 스프라이트 제작 방법 분석 — CuSurvive 방식과 SmashNine (2026-10-13)

- 요청: 사용자 2026-10-13 "@CuSurvive/docs/sprite-motion-guide.md 이 내용을 확인하여, 다른 게임 작업에서 효과적으로 적용중인 스프라이트 제작 방법을 분석하라."
- 읽은 것: `CuSurvive/docs/sprite-motion-guide.md`(2026-10-12), `CuSurvive/scripts/run-bakeoff/README.md`(공통 정리 도구). SmashNine 쪽은 이번 주 ART-23~34 보고서와 사용자 지적.

## 한 줄 요약

CuSurvive는 **동작 한 벌을 Codex 이미지 생성으로 한 장에 통째로 새로 그리고, 스크립트는 시트 전체에 같은 정리(배율 하나 · 바닥 · 팔레트 · 투명)만 한다.** 그리고 **사용자가 모션 뷰어에서 후보를 고른 뒤에만 게임에 넣는다.** SmashNine에서 생긴 문제는 거의 모두 이 두 가지를 어긴 데서 나왔다.

## CuSurvive에서 통한 것

| 요소 | 내용 |
| --- | --- |
| 한 장 생성 | 동작 하나의 모든 칸을 한 이미지에(2048×1024, 512 정사각 칸 4×2), 칸마다 자세를 글로 지시. 같은 그림 안이라 얼굴·비율·크기가 저절로 맞음 |
| 프롬프트 구조 | 용도(`stylized-concept`) → 입력 그림마다 역할("생김새·비율·도트 완성도 기준, 자세는 따라 하지 말 것") → 요청 → **칸마다 자세 글**(가장 중요) → 지킬 것 목록(얼굴·눈 색·머리·장식·옷·색, "모든 칸 같은 머리 크기·몸 너비") → 배치(같은 배율·같은 바닥, 칸마다 크기 맞추기 금지) → 단색 크로마 초록 배경 → 도트 스타일 → 금지 목록(칸 수, 팔 둘·손 둘, 효과 없음, 글자 없음) |
| 공통 정리 도구 | `normalize.py` 하나: 시트 전체에 **배율 하나**(서 있는 동작은 몸 높이, 서 있지 않은 동작·편집본은 `fixed:`), 바닥선 고정·공중 높이 보존, 캐릭터별 팔레트, 이진 알파, 지금 게임 줄과 나란한 `compare.png`, 확대판, 수치(`metrics.json`) |
| 효과 | 캐릭터 그림에 넣지 않는다. 효과는 게임이 따로 그린다 |
| 손질 | 남은 픽셀·끊긴 연결만. **팔다리를 옮기거나 그려 넣지 않는다** — 틀린 칸은 다시 생성 |
| 검수 | 리드가 모든 칸을 2배로 직접 + 게임 크기로도. Codex 자기 보고를 믿지 않음 |
| 결정 | 후보를 뷰어 "동작 겨루기"에 나란히 → 사용자 판정(`decisions.json`) → 채택된 것만 게임에, 나머지는 보관 |
| 고치기 | 채택본을 조금 바꿀 때는 시트 전체 편집(`precise-object-edit`), 바꿀 것만 지시 + 지킬 것 목록 |

## SmashNine에서 생긴 문제와 CuSurvive의 답

| SmashNine에서 생긴 일 | 원인 | CuSurvive의 답 |
| --- | --- | --- |
| 한 동작 안에서 크기가 튐(Frey spike 절반↔1.5배) | 칸마다 따로 맞춘 축소·확대 | 시트 전체에 배율 하나 |
| 프레임마다 얼굴·그림체가 다름 | 다른 생성에서 온 칸을 섞음(ART-23+28) | 한 동작 = 한 생성 |
| 칸 넘침(51칸, 116칸) | 생성 그림을 고정 폭으로 자름 | 넓은 정사각 칸(512)에 여백을 두고 생성, 정리 도구가 칸 단위로 처리 |
| 머리 두 개(ART-32) | 머리를 덮어 붙여 "머리 크기 규칙"을 맞춤 | 부분을 붙이거나 옮기지 않음, 틀리면 다시 생성 |
| 머리 측정이 실제와 다름(ART-33·34) | 칸마다 머리를 재서 배율을 정함 — 리본·머리카락을 상자로 잡음 | 머리(얼굴 너비) 배율은 팔 벌린 자세에서 지나치게 커져 쓰지 않음. 몸 높이 또는 고정값 |
| Nova 걷기 색이 청록 한 가지로 | 팔레트 양자화를 유닛마다 따로 구현 | 캐릭터별 팔레트 파일 + 공통 도구 |
| 줄무늬·사각 테두리 | 효과를 칸 안에 맞추려 자름 | 효과를 캐릭터 그림에 넣지 않음 |
| 문제 그림이 바로 게임에 들어감 | 새 그림을 바로 기본 경로에 넣는 규칙 | 뷰어에서 사용자가 고른 것만 게임에 |
| 같은 브랜치 이름이 옛 커밋을 씀 | `new-unit.sh` 동작 | 과제마다 새 브랜치 이름 |

## SmashNine에 적용할 것

1. **한 동작 = 한 생성**, CuSurvive 프롬프트 구조 그대로. 다만 SmashNine은 옆모습(측면)이고 칸이 128px(6열)이라, 생성은 512 정사각 칸으로 크게 하고 정리 도구가 128로 줄인다.
2. **공통 정리 도구** `tools/sprite_pipeline/`(Codex 런타임 Python, numpy·Pillow): CuSurvive `normalize.py`를 SmashNine 계약에 맞춤 — 128 칸 · 6열 · 발 y=120 · 공중 높이 보존 · 시트 전체 배율 하나 · 캐릭터별 팔레트 · 이진 알파 · D32 ①(1px 빈 테두리, 기본 시트 4px 여백) · 지금 게임 줄과 나란한 비교판.
3. **D32 ②(머리 크기)를 배율 하나로 지킨다.** 기준 대기 자세와 머리가 같아지는 배율을 시트에 한 번 정하고, 칸마다 다시 재서 맞추지 않는다. 확인은 리드의 눈(2~3배) + 몸 높이 범위·면적 편차 수치.
4. **D32 ③(효과)는 "게임이 따로 그려 합친다"로 적용.** SmashNine은 이미 기술마다 효과 그림(`attack_vfx`, `effects/skill`)을 게임이 그리므로, 기술 시트에는 캐릭터만 그린다(ART-32·33의 효과 층 합성은 하지 않음).
5. **후보 → 뷰어 → 사용자 판정 → 게임.** 캐릭터 동작을 바꾸는 그림은 저장소의 `art/bakeoff/`(Godot 프로젝트 밖)에 후보로 두고, 모션 뷰어에 "지금 vs 후보"로 띄운다. 게임 시트는 사용자가 고른 뒤에 바꾼다.
6. **검수 규칙:** 모든 후보의 모든 칸을 2배 이상으로 직접 보고(얼굴 하나, 크기, 다리 교대), 빌더 스크립트에 몸 일부를 붙이는 코드가 없는지 확인. Codex 숫자는 참고만.
7. **작법(치비 동작):** 착지에서 가장 낮고 뜸에서 가장 높게, 머리카락·망토·치마는 한 칸 늦게, 치비에게 어른식 팔 흔들기 금지(캐릭터다운 고정 자세), 주먹이 얼굴을 가리지 않게, 이어지는 동작(대기 ↔ 걷기, 공격 끝 ↔ 대기)을 나란히 놓고 크기·위치 튐 확인.
8. **운영:** 과제마다 새 브랜치 이름, Codex 동시 2개, 크로마 초록이 정확하지 않거나 격자선이 생기면 준비 단계에서 평탄화, Godot 프로젝트 안에 CSV 금지.

## 그대로 가져오지 않는 것

- 3/4 시점·256/512 칸·바닥 y=246 같은 CuSurvive 수치(SmashNine은 측면·128·y=120).
- 유료 도구(PixelLab 등) — CuSurvive에서도 쓰지 않기로 함.
- "얼굴 너비로 배율 맞추기"(`--scale-by head`) — CuSurvive에서도 팔 벌린 자세에서 실패.
