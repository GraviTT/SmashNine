- 회색 마네킹으로 두 걸음을 분리했고, 3번은 첫 생성의 들린 발이 뒤에 남아 두 번째 생성으로 교체했다.

## 생성과 정규화

내장 이미지 도구로 프레임을 한 장씩 생성했다. 1번은 대기 프레임 + 1번 회색 마네킹 + 기존 게임 걷기 1번을 참조했다. 2–8번은 모두 대기 프레임 + 해당 회색 마네킹 + 승인한 1번만 참조했고, 이웃 프레임은 쓰지 않았다.

정규화는 128px 셀, LANCZOS, 선명화 60, 자동 디스필, 팔레트 없음, `--ground-all`이다. 각 생성물에 하나의 배율만 적용했다. 최종 보브는 `walk_bob.py`만 사용했고 다른 상하 이동은 하지 않았다.

## 4× 육안 판정

- 의상: 8칸 모두 양쪽 다리가 보라색 무릎부츠이며 줄무늬 스타킹·발목부츠가 없다. 드레스와 흰 프릴도 대기 자세와 맞는다.
- 장비: 8칸 모두 완드는 가까운 손 앞쪽에 세워져 있고 별이 오른쪽 위에 있다. 각도 변화는 약 15° 안이다.
- 다리: 1번과 5번은 앞쪽 깊이의 다리가 반대이며, 3번은 먼발, 7번은 가까운 발이 전방으로 들려 있다. 회색 마네킹의 contact/down/passing/up 두 주기를 따른다.
- 보브: `bob.png` 아래 행에서 다리 seam 자국은 보이지 않는다.
- 13.3fps 판정: **가까운 발 한 걸음 → 먼 발 한 걸음의 두 교대 보행으로 읽히며, 몸 보브 튐과 의상 깜빡임은 보이지 않는다.**

`walk.gif`는 4×, 프레임 시간 80/70ms 교대(평균 13.3fps)로 만들었다. 로컬 `file:` URL은 브라우저 보안 정책으로 직접 열리지 않아, 재생 판정은 동일 순서의 4× `bob.png`·`feet.png`와 GIF의 프레임/시간 정보를 함께 확인한 결과다.

## 남은 문제

- 독립 생성이라 머리카락 끝, 치마 주름, 부츠 하이라이트가 프레임마다 조금 달라진다. 의상 종류나 완드 위치가 바뀌는 수준의 flicker는 아니다.
- 이 파일은 후보이며 실제 게임 시트에 넣지 않았다. 모션 뷰어에서 사용자가 최종 선택해야 한다.
