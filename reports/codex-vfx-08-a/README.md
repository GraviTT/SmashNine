# CODEX-VFX-08 A — 날카로운 순간

Frey 점프·공중 점프·작은/큰 착지 4종, Luna 작은/큰 별의 발사·비행 꼬리·적중 여운 6종을 **후보로만** 제작했다. 첫 순간의 흰 섬광, 강철 선과 깃털, 분홍/금색 별을 강조하며 빠르게 작아진다. 모두 더하기 혼합, 1 art px = 1 world px다. B 폴더와 B 이름의 파일은 열지 않았고 제품 소스와 pixelfx 사본은 변경하지 않았다.

## 측정

첫 가시 프레임은 전부 **F1 = 0초**다. 시간은 게임 배율 100%에서 `frames/fps`, 크기는 전 프레임의 알파가 있는 픽셀을 합친 외접 상자다. 정점은 각 프레임의 `sum(max(R,G,B))`가 최대인 프레임이며, 체감 강도를 뜻하지 않는다. 상세 원자료는 [measurements.json](measurements.json), 재현 검사는 [audit.json](audit.json).

총 **89프레임**. 큰 착지의 실제 외접 상자는 작은 것보다 너비 1.45배·높이 1.58배다. 빈 여백을 줄인 최종 칸은 착지 최대 178×42, 꼬리 최대 96×40이다. 모든 칸은 그려진 외접 상자에 최소 2px 여백만 두고 짝수 크기로 맞췄다. 위치·회전·발동 조건은 각 PNG 옆 JSON의 `anchor`, `attach`에 기록했다. 꼬리는 비어 있는 별 중심까지 잘랐으므로 앵커 x가 칸 밖에 있다(작은 것 90, 큰 것 128). JSON 앵커를 그대로 사용하고 칸 안으로 제한하지 않는다.

## 확인한 것

- 실제 Frey/Luna 그림에 합성한 전 89프레임을 1배 및 최근접 4배 접촉시트로 직접 열어 검수했다. `qa/*-1x.png`, `qa/*-4x-*.png`에 같은 프레임과 시각을 표시했다.
- 세 번의 시각 검수 단계: 초안에서 뭉친 깃털·막대 같은 접촉선 발견 → 깃털 간격과 가늘고 비스듬한 섬광 수정 → 밝기 하한 때문에 생긴 빈 끝 프레임을 작은 입자 소멸로 수정했다. 별의 번짐 반경도 줄였다.
- 검수 벤치의 동작 행을 수정했다. Luna 12프레임 변신은 두 행이므로 `star_side`는 물리 행 7, 8프레임 걷기 다음의 Frey 피격은 물리 행 7이다. Luna 발사 그림은 발사 순간 F3부터 채택 fps로 진행한다.
- 알파 0/255 이외 **0픽셀**, 1px 테두리 침범 **0픽셀**, RGB 최댓값 40 미만의 잔여 픽셀 **0개**. 굽기 전 48px 확장 캔버스로도 잘림 **0픽셀**. 원샷은 `t=duration`에서 모두 빈 그림이며 모든 저장 프레임에는 그림이 있다.
- 두 루프의 `t=0`과 `t=duration` RGB/알파 차이 **0**. 마지막→첫 그림의 차이도 루프 안의 최대 인접 차이보다 작다(작은 꼬리 81,947 / 84,802; 큰 꼬리 171,140 / 178,791, RGBA 절댓값 차이 합). 같은 입력 재렌더 해시가 일치했다.
- 여백 축소 전후 10종 모두 앵커 기준 전 프레임 RGBA 해시가 일치했다([crop-equivalence.json](crop-equivalence.json)). 그림·크기·배치·재생 시간은 그대로이고 저장할 빈 영역만 줄었다.
- 적중 여운의 중앙 `abs(x)<20, -22≤y≤22`와 꼬리의 투사체 중심 보호 반경(작은 것 16.5px, 큰 것 30px)에는 새로 그린 픽셀이 **0개**다. 이는 지정 영역 검사이며 모든 캐릭터·자세에서의 가림 판정은 아니다.
- 작은/큰 꼬리는 실제 속도 1050/930px/s와 수명 0.30/0.36초로 움직이는 별에 붙여 확인했다. [움직이는 검수 보기](preview.html), [APNG](moving-stars.apng), `qa/*-moving-1x.png`. 추가 패키지 설치 없이 Node로 작성했다.

## 시각 자료와 해석

[board.png](board.png)는 각 효과의 첫 순간 1배와 정점 부분 4배다. 적중 여운의 오른쪽은 기존 불꽃이 꺼진 F4(작은 것)·F6(큰 것)로, 이번에 추가한 별이 드러나는 시각을 보여 준다. **게임 아트 벤치 합성이지 Godot 경기 녹화가 아니다.**

게임 소스상 별의 22×22·40×40 값과 1.5배는 판정 크기다. 실제 별 PNG는 48×48·96×96 칸이며 `Projectile.set_effect_art()`는 `screen_scale=1`로 그린다. 검수는 이 렌더 경로를 따랐고 새 효과도 1배다. 기존 별의 긴 뒤꼬리·위 발사 때의 머리 겹침과 큰 `luna_comet_burst`의 큰 섬광은 후보에 포함된 그림이 아니다. 기존 적중 불꽃은 44fps, 혜성 폭발은 42.857fps·1.25배로 함께 그렸다.

**사람이 판단할 것:** 짧고 날카로운 시작이 실제 0.85배 경기에서 충분히 읽히는지, 큰/작은 착지가 다르게 느껴지는지, Luna 기본 별·폭발에 더한 장식이 도움이 되는지. 이것은 수치로 확인하지 못한 선호 판단이다. 지금/A/B 비교는 리드의 실제 경기 캡처와 시안 월드컵에서 해야 한다.

## 제한과 인계

- Godot 연결·8인 경기·웹 누적 p95/p99·은신/F2/중복 생성 검증은 수행하지 않았다. 카드의 후보 전용 쓰기 범위 밖이므로 리드가 채택 후 확인한다. 최종 Node 원본 그리기 측정은 중앙값 약 0.27~1.92ms, p95 약 0.79~19.42ms였으며 공유 PC의 측정이다. 원본 코드가 항상 2ms 이내라는 기준은 입증하지 못했다. 게임은 미리 구운 PNG를 사용하므로 이 값을 게임 성능으로 해석하면 안 된다.
- 카드 필수 산출물은 모두 남겼다. `.git`은 이 세션의 읽기 전용 경로여서 커밋하지 않았다. [commit.ps1](commit.ps1)은 이번 파일과 작업 카드만 명시적으로 추가하며 `git add -f`를 사용하지 않는다.
- 다시 굽기: 저장소 루트에서 `node art/bakeoff/effects/pixelfx/frey/a/bake.mjs`, `node art/bakeoff/effects/pixelfx/luna/a/bake.mjs`. 검수 그림은 `node reports/codex-vfx-08-a/qa.mjs --animation`, 규격 검사는 `node reports/codex-vfx-08-a/audit.mjs`.
- 공통 벤치는 보고서 폴더의 `bench.mjs`에 복사해 pixelfx 경로를 고쳤다. `setup.mjs`는 메타데이터 기반 모듈 생성기이며 명시적으로 실행할 때만 소스를 쓴다. 원본 모듈은 각 캐릭터 A의 `src/`에 있다. 기존 Frey 시범 A 파일은 보존했다.
