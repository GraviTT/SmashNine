# SmashNine 후보 비교

기존 모션 뷰어와 별개로 게시하는 후보 선택 페이지다. 지금 게임, 체크포인트의 옛 후보, 이 브랜치의 새 후보를 나란히 보여 주고 **한 줄당 하나**를 `candidate_picks`에 저장한다. 이 도구는 게임에 그림을 적용하지 않는다.

## 빌드와 검증

저장소 루트에서 Node 24만 사용한다. 패키지 설치, 네트워크, Godot 실행은 필요 없다.

```powershell
node tools/compare_viewer/build.mjs
node tools/compare_viewer/verify.mjs
```

- `build.mjs`는 수정하지 않은 `tools/motion_viewer/build.mjs`를 실행하고 그 `dist/index.html`의 `const M`을 읽는다. 기존 뷰어의 무시된 `dist/`만 다시 만들어진다.
- 게임 행 표·채택된 재생 속도는 기존 manifest를 따른다. 게임에 없는 동작은 가장 높은 버전의 JSON 속도를 쓴다. 정지 초상화는 1프레임, 현재 투사체 PNG는 정지 그림으로 비교하며 후보의 fps를 공통 시계로 쓴다.
- 새/옛 구분과 설명은 리드가 작성한 `changes.json`을 사용한다. Git 체크포인트 이후 추가된 PNG를 대조하며, 누락·잘못된 경로·표시되지 않은 새 항목은 빌드를 실패시킨다. 대응표를 자동 수정하지 않는다.
- 수호자 충격파는 투사체의 독립 선택 행이다. 현재 모션 빌더가 몬스터 추가 행으로도 수집하므로 그 위치에서는 제외한다. 공용 충격파 v1은 선택할 수 없는 참고 타일이다.
- 옛 몬스터 수리본은 몬스터마다 한 선택 행에 게임 `ART_ROWS`의 4개 동작을 모두 배치한다. 수리본 하나를 고르면 시트 전체에 대한 선택이다.
- `verify.mjs`는 파일·Git 대조와 Node 모의 DOM/Image/캔버스/DB 검사다. 결과는 `reports/codex-tool-04/checks.json`. 실제 브라우저 화면이나 Artifact DB를 검사하지 않는다.

현재 데이터: **222줄 / 새 버전 있는 64줄 / 게임 시트 수리본 비교 21줄 / 새 버전 없음 안내 5줄**. 선택 후보 267개 중 새 후보는 66개이며, 옛 시트 수리본은 별도로 15쌍이다. `새 버전 없음` 5줄 중 리오 남성 승리·걷기는 부분 수리 새 버전도 있으므로 두 배지가 함께 나타난다.

## 조작

- 재생·멈춤, 속도 ×0.25–×1.5, 배경, 크기는 페이지 전체에 적용한다. 동작을 줄이라는 시스템 설정에서는 멈춘 상태로 시작한다.
- 한 비교 행의 모든 타일은 하나의 fps를 공유하고 자기 프레임 수로 반복한다. 비반복 동작은 끝에서 0.6초 더 머문다. 시트 크기가 달라도 동일한 캔버스 크기·배율과 발 기준선을 사용한다.
- 화면에서 320px 안쪽으로 가까워진 행만 이미지를 불러오고 재생한다. 이미 읽은 그림은 재사용한다. 화면을 벗어난 행은 그리기를 멈춘다.
- 후보 또는 `둘 다 아님`을 누르면 즉시 저장한다. `둘 다 아님`도 검토를 마친 선택이므로 고른 줄 수에 포함된다. `고르기 지움`은 미선택으로 되돌린다.
- 메모는 최대 300자다. 후보를 고를 때 현재 메모를 함께 저장하며, 이후 수정은 `메모 저장`을 누른다. 입력 중에는 저장하지 않는다.
- `고른 것` 목록에서 행으로 이동한다. 필터에 숨은 선택 행은 전체 보기로 바꿔 표시한다.
- DB가 없거나 `use("db")`가 null을 돌려주면 선택·메모만 비활성화하고 `저장은 게시된 페이지에서만 됩니다`를 표시한다. 이미지 비교와 재생은 계속 사용할 수 있다.

## 새 Artifact에 게시

**기존 모션 뷰어 URL에 덮어쓰지 않는다.** 리드가 새 Artifact를 만들고 `db` 기능을 활성화한다. 초기 게시에 필요한 도구별 정확한 옵션은 리드가 게시 환경에서 확인한다. 이 작업에서는 게시 API를 호출하지 않았다.

| 항목 | 값 |
|---|---|
| HTML | `tools/compare_viewer/dist/index.html` |
| root | `tools/compare_viewer/dist` |
| 전체 첨부 파일 목록 | `tools/compare_viewer/dist/files.json` |
| 분할 목록 | `files-1.json`, `files-2.json` 순서 |
| 저장 기능 | `db`, 컬렉션 `candidate_picks` |

목록의 경로는 `root` 기준이다. HTML은 별도로 전달하므로 목록에는 포함되지 않는다. **각 배치는 HTML 한 파일과 그 바이트까지 합쳐 250파일·60,000,000바이트 이하**다. 현재 두 배치는 HTML 포함 250개와 77개다. 전체 버전은 중복 HTML을 한 번만 세어 326파일·23,831,088바이트이며 511파일·256,000,000바이트 한도 안이다.

리드는 두 목록을 **같은 Artifact 버전**에 순서대로 추가하고 앞 배치가 유지되는지 확인한다. 새 버전마다 파일을 교체하는 게시 동작이라면 목록 두 개를 각기 완결된 새 버전처럼 게시하면 안 된다. 실제 분할 업로드 동작은 이 오프라인 작업에서 확인하지 않았다. 같은 Artifact를 나중에 갱신할 때는 기존 `db` 선언과 선택 데이터를 보존한다.

글꼴은 기존 뷰어와 같은 Google Fonts CSS 참조를 사용한다. 빌드·검증에서는 요청하지 않으며, 완전 오프라인 화면은 설치된 한글/시스템 글꼴로 대체된다. 외부 JavaScript는 없다.

## DB 형식과 조회

`window.claude?.use?.("db")`를 한 번 호출하고 `candidate_picks` 전체를 `onSnapshot`으로 한 번 구독한다. 저장 호출은 `db.collection("candidate_picks").doc(id).set(record)`다.

문서 id: **`<kind>~<id>~<row>`**. 이전 모션 뷰어의 버전까지 포함한 4부분 id와 다른 형식이며, 새 Artifact에서 사용한다.

- `kind`: `fighter`, `monster`, `projectile`, `face`, `legacy_sheet`
- `id`: 시트 stem(예: `nova_female`), 몬스터/투사체 id, 초상화 폼 stem
- `row`: 동작 이름, `projectile`, `shockwave`, 표정 이름, 옛 시트는 `sheet`
- `choice`: `v1`, `v2` 등의 버전, 수리본 `fix1`, 또는 `none`
- `file`: 고른 그림의 저장소 경로 `art/bakeoff/...`; `none`이면 `null`
- `options`: 저장 당시 선택 가능한 버전 문자열 배열. 마지막 항목은 `none`; 참고 타일은 제외
- `picked`: 선택 여부. `none`을 고르면 `true`, 고르기를 지우면 `false`
- `note`: 메모(최대 300자), `picked_at`: 마지막 저장 시각(ISO UTC)
- `viewer`: `compare`, `commit`: 빌드 시점의 전체 Git HEAD

형식 예시이며 실제 선택 기록은 아니다.

```json
{
  "kind": "fighter",
  "id": "luna",
  "row": "victory",
  "choice": "v3",
  "file": "art/bakeoff/luna/luna-victory-v3.png",
  "options": ["v1", "v2", "v3", "none"],
  "picked": true,
  "note": "형식 예시",
  "picked_at": "2026-10-25T13:00:00.000Z",
  "viewer": "compare",
  "commit": "3449a1dbe8a02814f1415bd9def735fc16b40a33"
}
```

리드는 **새 비교 Artifact**를 대상으로 **`ArtifactData list candidate_picks`**를 실행한다. `viewer === "compare"`이고 `picked === true`인 문서를 읽는다. `choice === "none"`은 현재 그림 유지/추가 안 함이며, 나머지는 해당 `file`과 JSON을 검토한 뒤 별도 반영한다. 수호자 충격파의 코드 연결과 수리본/새 6줄 시트 사이의 최종 적용 판단도 별도다.

문서 id·종류·행, 선택·경로, 옵션 배열, 메모 길이, 날짜, commit이 유효한 기록만 화면에 반영한다. 현재 선택지에 없는 버전이나 다른 뷰어 형식은 세지 않는다. 향후 옵션이 늘어도 현재 유효한 선택과 파일을 가리키는 이전 기록은 유지할 수 있도록 `options`는 저장 당시 목록으로 취급한다.

## 리드가 실제 브라우저에서 확인할 것

1. 375px에서 페이지 가로 넘침 없이 타일 두 개씩, 컨트롤 줄바꿈, sticky 바·노치 여백이 맞는지.
2. 밝은/어두운 테마와 Google Fonts, PNG 디코딩, 발 기준선·동작 타이밍·끝 자세 유지가 눈으로 자연스러운지.
3. 실제 DB에서 후보 교체·`none`·메모·지우기 저장 후 새로고침 복원, `ArtifactData` 조회 결과가 맞는지.
4. 위아래 이동 시 이미지 지연 로딩·메모리·프레임 성능, 키보드 라디오 선택·포커스, 두 배치의 파일 유지 여부.

오프라인 검사 통과를 위 브라우저 검증의 완료로 해석하지 않는다.
